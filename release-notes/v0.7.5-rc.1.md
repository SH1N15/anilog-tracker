# AniLog v0.7.5-rc.1

本地验收候选版，尚未发布到 GitHub。正式版与 Latest 仍为 v0.7.4。

## 修复

- 取消追番不再被 Bangumi 的旧“在看”记录、Android 旧快照或 WebDAV 旧重追标记恢复；已完成历史保留。
- 取消操作改为独立幂等命令，重复点击不会重新加入。
- 本地评分、状态和进度修改不会在立即同步时被旧拉取覆盖；网络途中再次修改的记录会复核版本。
- 清空评分正确写回 Bangumi；上传失败保留本地修改，后续重试。
- 自动冲突策略不再假装使用 Bangumi 不可靠的修改时间；相同值正常收敛，写回遵守同步开关。
- 启用 Bangumi 同步后，顶栏手动同步包含账户写回。

## 请求与缓存

- 当季列表按 24 小时、历史季度按 30 天缓存，仅浏览时按需刷新；已有快照先显示。
- 新追番立即补齐日程，正在追的作品保留原有检查频率；想看/搁置按日、已完成按月刷新。
- 季度、追番与 Android 前后台复用按 AniList ID 保存的缓存；只请求过期或缺失的 ID，每批最多 50 个。
- 合并重复请求，手动刷新保留一分钟冷却，限流/失败退避跨重启保留。
- 不再把没有 AniList 映射的 Bangumi ID 发给 AniList；精确时间仍只保留七天，不按周播锚点猜测。

完整契约见 [请求策略](../docs/ANILIST_REQUEST_POLICY.md) 与
[观看和同步回归](../docs/WATCH_STATE_REGRESSIONS.md)。

## 安装与验收

- 请同时升级 Windows 和 Android 的对应 edition。
- Windows 先退出主窗口和托盘，备份安装目录 `data`，再覆盖安装。
- Android 直接覆盖安装，不要卸载；`versionCode=15`，高于正式 code 13 和曾分发的 code 14。
- Android 只交付 `arm64-v8a`，沿用既有发布证书。Windows 没有商业代码签名。
- 优先验证取消追番后连续同步、修改评分/状态后立即同步、双端完成/撤销，以及关闭自动任务后的播出通知。
- 这些是待用户验收的候选包，不代表已在用户真机完成验收。

## 构建验证

- Rust Standard 195 项、Original 40 项测试通过。
- Android 两个 edition 各 41 项 JVM 测试通过，两份 ARM64 Release APK 构建成功。
- 两份 Windows NSIS 安装包构建成功，ProductName 与 ProductVersion 检查通过。
- 12 个 Node 回归脚本、双版前端构建通过，生产依赖审计为 0 漏洞。
- 320/390/768/1280 像素的隔离浏览器检查验证取消命令、评分后同步、季度强制刷新及非季度页不拉取季度列表；没有使用真实账户。
- 两份 APK 均验证既有发布证书、`versionCode=15`、仅 `arm64-v8a` 与 16 KB ZIP 对齐。
- 构建仍有上游 Java/Gradle 弃用提示；Android Original 中未使用的 Rust 批量请求辅助代码有 dead-code 提示，不影响构建和签名检查。
- 没有修改或安装到用户的 PC/手机，也没有读写真实 WebDAV/Bangumi 记录。
