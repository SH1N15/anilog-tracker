# AniLog v0.7.5-rc.2

本地测试候选版，修正 rc.1 验收中发现的持续缺少准确日程和 Android 冷启动显示异常。
未公开发布；GitHub 正式版与 Latest 仍为 v0.7.4。

## 修正

- 移除 AniList `Media.airingSchedule` 不支持的 `sort` 参数，修复整批日程查询被 HTTP 400 拒绝、始终没有分钟级缓存的问题。
- 修正第二季等独立季度的集号匹配：通过至少两个唯一日期锚点确认本季集号，保留 Bangumi 的 episode 身份，再应用 AniList 的改期时间。仍不按周播规则推算。
- 新增追番先复用已验证缓存，并只请求该作品；手动刷新也刷新 Bangumi 逐集缓存，保留一分钟冷却。
- 初次读取状态失败会有限重试，真实快照就绪前不展示默认空列表和关闭的同步开关；Android 原生快照读取放到工作线程。
- 状态保存串行完成写入、落盘和原子替换，避免并发同步争用同一个临时文件。已有文件损坏时不再静默覆盖为空状态。
- 日程请求失败会在完整同步结果中报告；手机内容区也显示同步反馈。
- 保留 rc.1 的取消追番、编辑后同步和分级缓存修正。

## 安装与验收

- Android `versionCode=16`，沿用既有证书，仅 `arm64-v8a`，直接覆盖安装，不要卸载。
- Windows 先备份安装目录 `data` 并退出应用和托盘，再覆盖安装。安装器没有商业代码签名。
- 请同时升级两个平台的对应 edition；不能直接将 Android 覆盖降级到 code 15 或更早。
- 旧版留下的请求冷却仍会被遵守。出现冷却提示时等待其结束，无需清空数据或反复重启。
- 重点验收两部反馈作品的分钟级日程、加入追番后刷新，以及杀掉 Android 进程后直接重开时的列表和同步开关。
- 真机冷启动、后台通知及用户数据覆盖升级仍需维护者验收，没有安装到用户设备或修改真实云端记录。

契约与公开数据样本见 [观看状态回归](../docs/WATCH_STATE_REGRESSIONS.md)、
[AniList 请求策略](../docs/ANILIST_REQUEST_POLICY.md)。

## 验证

- Rust Standard 205 项、Original 44 项通过；Android 两个 edition 各 45 项 JVM 测试通过。
- 12 个 Node 回归脚本、双版前端构建通过，生产依赖审计 0 漏洞。
- 双版 320/390/768/1280 宽度的隔离浏览器检查通过，包括启动读取失败重试、原有设置恢复、准确时间和手机同步反馈。
- 实际公开接口确认修正后的 AniList 批量查询返回两部作品；测试不使用真实账户 Token，不读写云端用户收藏。
- 两份 Windows NSIS、两份 Android ARM64 APK 构建成功，版本均为 `0.7.5-rc.2`。
- APK 包名、`versionCode=16`、既有签名证书、单 ARM64 ABI 和 16 KB ZIP 对齐通过验证。
- 仍有既有 Java/Gradle 弃用提示及 Android Original 中 6 项未使用 Rust 辅助代码提示，不影响构建。
- 没有连接可供验收的 Android 真机，也没有安装到用户当前的 Windows 目录；真机验收尚未完成。
