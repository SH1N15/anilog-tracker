# AniLog v0.7.5-rc.4

本地测试候选版，未公开发布。GitHub Latest 仍为 v0.7.4。

## 修正

- Windows 后台同步循环不再静默停摆：单轮 panic 或异常退出会留下 WARN 日志并自动重建循环（rc.3 事故中 AniList 轮询与 WebDAV 循环停摆约 8 小时，无任何日志），每轮附 INFO 心跳，停摆时日志缺心跳即可定位。
- 状态文件字段损坏（非数组）不再 panic 同步路径；任务排序与 seenAiringEvents 写入优雅降级，安卓快照合并同样加固。
- 待看提醒发送前若坚果云数据超过 30 分钟未同步，先拉取合并一次再计数；rc.3 事故中安卓端早已完成的集，PC 端 20:00 准点提醒误报的场景不再发生。拉取失败不阻塞提醒。
- 经 WebDAV 合并进来的新播出任务（其他设备 24 小时内产生的 airing 待看）现在触发与轮询路径相同的"追番已更新"通知，每个任务 id 只发一次；本地动作、已完成与旧历史不命中。
- 安卓任务勾选/撤销/追番变更后，除进程内唤醒外再排一个 WorkManager 立即同步：前台进程被厂商省电策略杀掉后，上传合并仍会完成（KEEP 幂等）。
- 安卓冷启动不再把整轮 JNI 快照往返作为进入界面的门槛：`get_state` 立即返回内存快照，原生事件消费移到后台，完成后经 state-changed 刷新界面；setup 阶段与 configure 桥接均附耗时日志（logcat `AniLog` tag），用于定位"正在读取本地数据"卡顿。
- 安卓开 app 不再补发 20:00 每日汇总（checkMissed=false）：用户已在看界面，补发只会被感知为重复通知；开机补发（BootReceiver）保留。20:00 正点仍由 AlarmManager 发送。
- 保留 rc.1/rc.2/rc.3 的取消追番、同步冲突、缓存与异常完成历史修正。

## 安装与验收

- Windows 和 Android 请同时覆盖升级对应 edition。Windows 先备份 `data` 并退出应用和托盘。
- Android `versionCode=18`，仅 `arm64-v8a`，沿用既有发布证书。直接覆盖安装，不要卸载。
- 本版本不能直接覆盖降级到 code 17 或更早；Windows 安装器仍可能提示"未知发布者"。
- 重点场景：安卓端勾选一集后 1 分钟内，PC 端手动同步或后台循环应能看到完成状态（不再等到次日）；PC 端后台循环停摆时日志应有 WARN + 心跳中断证据。
- 开 app 不再弹出 20:00 每日汇总；正点通知仍照常。
- 冷启动应明显更快；如仍卡顿，请回传 logcat 中 `android setup *` 与 `configure bridge finished in *ms` 日志。
- 真机覆盖升级、强制停止后重开和跨端同步仍需维护者验收；没有改动已安装应用、真实本地数据或云端收藏。

回归契约见 [观看历史与同步](../docs/WATCH_STATE_REGRESSIONS.md)。
