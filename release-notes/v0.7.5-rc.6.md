# AniLog v0.7.5-rc.6

本地候选版，未公开发布；GitHub Latest 仍为 `v0.7.4`。

## 本轮修复

- 修复 Windows 在 AniLog 已运行时切换 VPN/系统代理后，Bangumi、AniList 或 WebDAV 仍沿用启动时网络路径的问题。每次网络操作都会重新创建启用系统代理发现的 HTTP 客户端，因此无代理时直连，开启代理时走当前系统代理，切换后无需重启应用。
- 修复 Android 冷启动仍可能卡在启动页的问题。本地 Rust 快照可立即供界面读取，旧数据迁移、原生事件消费和后台配置改为 setup 之后串行执行，完成后再刷新状态并启动长期同步任务。
- Android 原生桥接调用增加进程内互斥，避免冷启动初始化、前台同步和配置并发进入 JNI 插件而互相阻塞或用旧快照覆盖新状态。
- 增加网络客户端生命周期和 Android 启动顺序契约测试；Android `versionCode` 递增到 `20`，四件产物独立保留，不覆盖 rc.5 或正式版附件。

## 真机验收重点

1. Windows 覆盖安装 rc.5，保留原安装目录下的 `data`。
2. AniLog 保持运行，按“无 VPN -> 开启 VPN -> 关闭 VPN”顺序反复测试 Bangumi、AniList 与 WebDAV；三段都不应要求重启 AniLog。
3. Android 覆盖安装旧测试版，不卸载、不清除数据；Standard 与 Original 不要混装。
4. Android 连续杀后台并冷启动至少 5 次，确认不会卡启动页、清空追番或重置 Bangumi 开关。
5. 复测后台同步、通知、每日汇总、更新时间、进度和观看历史；Original 不出现 Bangumi 设置或请求。
