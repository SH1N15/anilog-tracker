# AniLog v0.7.5

## 重点修复

- 取消追番不再被 Bangumi 旧收藏、Android 旧快照或 WebDAV 旧记录恢复；只删除未完成任务，观看历史继续保留。
- 修改收藏状态、评分或观看进度后立即同步，不再被云端旧值覆盖；失败的本地写入会保留并在后续重试。
- AniList 请求按季度、追番状态和缓存新鲜度分级，合并重复请求并持久退避；新增追番立即补齐日程，普通季度浏览显著减少重复请求。
- 修复 AniList 日程查询参数和分季集号映射，保留逐集证据与临时改档；不按周播周期猜测下一集。
- 尚未播出的异常完成记录进入“待核对”，保留原始历史但不计入进度或自动写回，只有用户确认后才恢复。
- Windows 后台同步循环异常退出后自动重启并记录心跳；WebDAV 合并进来的新播出可触发通知，每日汇总发送前会刷新过期同步数据。
- Android 冷启动先显示可信本地快照，原生迁移、事件消费和配置在后台串行完成；开 app 不再误补发每日汇总。
- AniList、Bangumi 与 WebDAV 每次网络操作读取当前系统代理，开启或关闭 VPN/代理后无需重启 AniLog。

## 升级提示

- **请同时升级 Windows 和 Android 的对应 edition**，确保两端使用一致的同步、任务和观看历史规则。
- Windows 安装前备份安装目录中的 `data`，退出主窗口和托盘后覆盖安装。
- Android 直接覆盖安装，不要卸载或清除数据。正式版 `versionCode=21`，高于 `v0.7.4` 的 `13` 和 rc.6 的 `20`。
- Standard 与 Original 使用不同包名；Android 正式附件仅支持 `arm64-v8a`，并沿用既有发布证书。
- Windows 安装包没有商业代码签名，系统可能显示“未知发布者”。

## 验证

- Rust Standard 与 Original 测试通过。
- Android Standard 与 Original JVM 测试通过。
- Node 行为回归、两个 edition 的前端生产构建和生产依赖审计通过。
- Windows Standard/Original NSIS 安装包使用正式版本号重新构建并核对产品信息。
- Android Standard/Original 使用 JBR 21 和 `aarch64` 重新构建；包名、`versionCode=21`、既有发布证书、ARM64 单 ABI 和 16 KB 对齐通过。
- 维护者已完成 Android 冷启动与双端网络切换验收；私人备用网络入口不进入公开配置或发布资料。
