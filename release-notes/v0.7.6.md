# AniLog v0.7.6

修复换季后新番表全部显示“播出日待定”，以及旧追番长期停留在“待确认映射”的问题。维护者于 2026-10-01 完成候选版问题验收并授权正式发布。

## 更新内容

- 标准版运行时通过 Bangumi 与 AniList 季度目录核验关联，不再要求安装包里的旧映射表预先收录新季度作品。适用于跨季、跨年及电影、网络动画等类型。
- 有首播日期但没有精确时刻的作品显示“首播日期 · 时刻待定”；只在日期确实缺失时进入待定分组。日期级信息不创建精确通知，也不按星期推算每集播出。
- 旧追番已有 Bangumi 候选时，重新核验标题、类型与日期后完成映射。保留已完成观看历史、手动选择、主动跳过及存在歧义的记录。
- 升级后先显示旧季度快照，再后台更新，无需清缓存、清空记录或重新追番。
- Original 继续仅使用 AniList，不访问 Bangumi。本版不覆盖上游提供的作品时间。

## 安装与升级

- Windows Standard / Original：x64 NSIS 安装包。
- Android Standard / Original：仅 arm64-v8a，`versionCode=23`，沿用原发布证书，可覆盖 v0.7.5 及 v0.7.6-rc.1。
- 建议同时升级两个设备的对应 edition。Windows 退出包括托盘在内的程序后覆盖安装；Android 直接覆盖安装，不要先卸载。
- Windows 安装包未使用商业代码签名，系统可能提示“未知发布者”。

## 验证

- Rust Standard 223 项、Original 50 项；Android 两个 edition 各 51 项 JVM 测试。
- 15 个 Node 回归脚本、两个 Tauri 前端构建、生产依赖审计。
- 空内置映射表下的跨季度与跨年测试，覆盖 2027 年及 2032 年，并验证续作/分篇歧义、请求缓存、旧记录迁移和完成历史保留。
- 候选版完成实时公开接口隔离验证、320/390/768/1280 宽度界面检查及维护者问题验收。
- 四个正式附件使用 v0.7.6 重新构建，Android 验证包名、版本、正式证书、单 ABI 和 16 KB 对齐。
